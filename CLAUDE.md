# lossrunresearch — guide for the implementer

This repo holds requirements, research, decisions and code for a **workers' comp loss run ingestion POC on Azure** (.NET 10 backend, React front end) competing in a build-vs-buy bake-off against Nomad Data, Bevaya, SortSpoke and Convr.

Hard constraints for every task: Azure only; no labelled training data; minimize LLM calls by learning a carrier format once and replaying it deterministically (model = fallback); cell-level lineage and a tamper-evident audit log are required features, not nice-to-haves.

## Start here
1. `docs/requirements/poc-requirements.md` — the client's requirement document (two use cases, objectives, acceptance criteria, deliverables). Every task traces back to a scenario or deliverable in this file.
2. `docs/research/poc-strategy-report.md` — the synthesized strategy report. Read the first section (BLUF) and the section relevant to your task before touching code.

## Working rules for agents
- **Decisions get an ADR.** Any choice that deviates from the research (different Azure service, different model, different data store) gets a short `docs/decisions/NNNN-title.md` with context, decision, consequences.
- **Cite the research.** When a task brief or ADR relies on a number (price, limit, threshold), reference the doc and section it came from. Research notes carry inline source URLs; keep them.
- **Model names are configuration**, never literals in code. Learn model: `gpt-5.4-mini` until the brief 35 wake decides between it and `gpt-5.2` by the acceptance table (ADR 0004 amendment 1; `config/models.json`, versions in its `modelVersions`); production recommendation `gpt-5.2` (Data Zone Standard, US). Delta/classification model: `gpt-5.4-mini`. Do not use the GPT-4.1 family (retires Apr 2027).
- **Deterministic replay must have zero model calls**, and validators run on every document including replay hits.
- **Every billable call is metered** (`CostMeter` → `UsageEvent`), cost is attributed per document and per path, and prices live in `config/azure-prices.json`, never in code. See `docs/architecture/cost-tracking.md`.
- **Every extracted value carries lineage** (document id, page + polygon or sheet + cell, format version, model/prompt version, confidence) and every mutation is an append-only audit event (user, role, time, old→new, rationale).
- **Keep the canonical schema and validation rule catalog (R-01..R-34) in `docs/evaluation/`** as the source of truth; code generates from or validates against it, never the other way round.
- **Every upload produces a manifest** (`UploadManifest`: each file/segment with its classification, status processed | kept-not-processed | unsupported, reason, page range, blob path). Non-loss-run documents are never discarded: they stay in Blob under the same upload, are listed back to the user, and are indexed for the chat service. The API and UI show the manifest.
- **Azure SQL: all tables in the `dbo` schema**; no custom schemas. Ledger/temporal/history tables included.
- **Database deployment is plain T-SQL scripts in Liquibase-compatible style** (`db/changelog/` — one file per changeset, `--liquibase formatted sql` header, `--changeset author:id` markers, `--rollback` lines), even though we run them with `sqlcmd`/a .NET migrator, not Liquibase. **Every script is rerunnable**: `IF NOT EXISTS` / `CREATE OR ALTER` / idempotent data seeds; ledger tables guarded (they cannot be altered, so changes are new tables). A master `db/deploy.sql` or runner applies them in order and records applied ids in `dbo.SchemaChangeLog`. No EF migrations as the deployment mechanism (EF models may be generated/validated from the scripts).
- **UI is a deliberate design pass, not a template.** Figma Make prototype (accessibility-first, WCAG 2.1 AA mandatory at State Fund) is the visual reference; the implementer builds from design tokens + component specs + mock JSON matching real contracts, on the existing React stack (TanStack Table/Query, Zustand, RHF+Zod, Radix/React Aria). See `docs/ui/design-brief.md` (tokens, components, screens, a11y acceptance), `docs/ui/mock/` (API-shaped sample data), `docs/ui/figma-export/` (reference only — do not port its code).
- **Infrastructure is Terraform only** (no Bicep, no portal clicks). Any manual change gets captured back into Terraform or recorded in an ADR.
- Do not commit client documents, real loss runs, or anything with PII. Synthetic/public samples only.
- Prefer `docs/research/notes/` for any new raw research; update the table above when you add a document agents should read.
