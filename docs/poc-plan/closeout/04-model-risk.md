# 4. Model-risk documentation

## 4.1 Where models sit, and where they do not

| Component | Model? | Deterministic? | If the model is wrong |
|---|---|---|---|
| Layout (Content Understanding `prebuilt-layout`) | OCR / layout service | Same input gives the same output in practice | Values misread. Validators and totals catch most; low-resolution scans always go to review |
| Classification (loss run vs other, bundle split) | `gpt-5.4-mini` via the CU classifier | No | A loss run kept as "other": listed in the manifest, never discarded. A non-loss-run processed: rules fail, so review |
| **Learn** (a new carrier format) | `gpt-5.4-mini` (`learn_model`, configuration) | No, but its output is a *spec*, verified before publication | The spec is not published unless it passes the learn gate: the replay ties the printed totals, or meets the spreadsheet rules gate. Otherwise review with pre-fill |
| Delta repair (a format changed) | `gpt-5.4-mini` (`delta_model`) | No; verified as above | Escalates once to a full learn, then review |
| **Replay** (every later document of a known format) | **None** | **Yes** | — |
| Validation (R-01…R-26) | None | Yes | — |
| Analytics engine (41 metrics, what-if) | None | Yes; C# and TypeScript byte-identical | — |
| Chat | `gpt-5.4-mini` + `text-embedding-3-large` | No | Answers carry citations to tool results. Invented refs are dropped and reported. "Not found" is allowed. No chat output feeds a quote |

**This is the format-memory argument in risk terms.** Model risk is concentrated in a learn that happens once per carrier format, verified and versioned. A replayed format has no model to drift or retire.

## 4.3 Operating ranges and acceptable error (RS1)

- **Inputs within range:** native PDF, XLSX/CSV, and scans ≥ 300 dpi, delivered straight-through when every gate passes. Thresholds are in `docs/evaluation/scoring-protocol.md` §6:
  - claim number and DOI ≥ 98 % on native / XLSX;
  - ≥ 95 % on scans ≥ 300 dpi.
- **Outside the straight-through range, always reviewed:** faxes under 200 dpi, narrative statements, tableless segments (ADR 0009), and any document with a hard rule failure.
- **Confidence:** values carry confidence. Confidence never overrides a failing rule.

## 4.4 Failure-mode table (RS2)

| # | Failure mode | Detection | Fallback (and when it is invoked) | Rollback / shut-off |
|---|---|---|---|---|
| 1 | Wrong value delivered from a replay | R-01…R-26 on every document; printed totals must tie (R-10/R-11); lineage lets a reviewer verify any cell | A hard failure goes to review before delivery (immediate) | Retire the format version (`format.retire`): documents of that format go to learn or review |
| 2 | A learned spec that passes its gate but is subtly wrong | Shadow status until 3 clean replays or underwriter approval; validators on every replay | Shadow documents need confirmation (immediate) | Retire the version; the pre-bake-off reset retires every learned version |
| 3 | Format change at a carrier (drift) | Fingerprint and header diff; unmapped headers | Delta repair → one full learn → review (immediate) | The prior version stays available |
| 4 | Learn path unavailable (quota, risk check, outage) | Learn errors; the `LearnGate` cap | Review with pre-fill (immediate). Replay is unaffected | `learn_max_concurrent`; model names are configuration |
| 5 | Model retired or auto-upgraded | Retirement calendar (monthly, artefact 7); golden-set regression on change | Replay keeps working with no model. Learn and chat switch deployment by configuration | Pin the version; re-run the golden set before switching (runbook) |
| 6 | Classification misses a loss run | Manifest lists every segment with its classification; the underwriter sees "kept, not processed" | Reopen or re-upload (manual) | — |
| 7 | Duplicate learns under concurrency (found in the integration work) | Registry shows sibling versions | Lock held until commit (fixed) | Pre-bake-off reset retires the duplicates (runbook) |
| 8 | A planted or real source inconsistency (printed total ≠ rows) | R-10 / R-26 | Review; the reviewer corrects with a rationale (immediate) | — |
| 9 | Prompt injection through a document (chat) | Planted-instruction test; Defender for AI alerts | Tool-layer scope; documents are data; structured output | Chat can be disabled without affecting UC1 |
| 10 | Cross-quote leakage (chat) | `ScopeLeakageTests` (11 cases); live probes | Scope enforced at the tool layer, not by the model | — |
| 11 | Cost runaway | Per-document metering; monthly reconciliation to the bill; the learn cap | Learn cap; review instead of learn on low-resolution scans | Configuration |
| 12 | Unaudited change to a claim | `lossrun-db audit-proof` (temporal vs audit) | Detective on `Claim`; preventive on the ledger tables | Restore from temporal history; updatable ledger as the production option |

## 4.5 Monitoring and drift (RS3)

**Signals**
- per-carrier review rate and validation pass rate (registry stats);
- learn count per week;
- unmapped-header alerts;
- cost per document by path (the Costs screen);
- the monthly reconciliation;
- Defender for AI alerts.

**Drift tests**
- the golden set re-run on every model, prompt, glossary or rule-catalog change;
- a quarterly re-audit on a re-keyed production sample.
