# 6. RBAC configuration

## 6.1 People: application roles

The app roles live on the API's Entra app registration (`Auth__Mode=entra`). The POC demo host uses HTTP Basic with one user per person role, plus the quote system's service user. Their passwords exist only in Key Vault `devauth-users`, generated by Terraform.

Two roles were added after the close-out:
- **Engineer** (brief 26 Answers 3): works the Needs investigation queue and reads everything a reviewer reads, but cannot decide reviews or change values.
- **QuoteSystem** (brief 25 Answers 2): a service identity, least privilege. It reads the quote payload, upload manifests and integration status, and writes nothing.

| Capability | Applicant | Underwriter | UWManager | Admin | Engineer | QuoteSystem |
|---|:-:|:-:|:-:|:-:|:-:|:-:|
| Upload documents | ✓ (own) | ✓ | ✓ | ✓ | ✓ | — |
| See uploads and manifests | own only | all | all | all | all | all |
| See documents, pages, audit trails, the review queue | own documents only | ✓ | ✓ | ✓ | ✓ | — |
| Decide reviews; override with rationale; reopen | — | ✓ | ✓ | ✓ | — | — |
| Analytics and what-if (read) | — | ✓ | ✓ | ✓ | ✓ | — |
| Context edits, memo export, follow-ups, push to quote system | — | ✓ | ✓ | ✓ | — | — |
| Quote payload (`GET /quotes/{id}/quote-payload`) | — | ✓ | ✓ | ✓ | ✓ | ✓ |
| Integration status (`GET /quotes/{id}/integration`) | — | ✓ | ✓ | ✓ | ✓ | ✓ |
| Chat, quote scope / organisation scope | — | ✓ / — | ✓ / ✓ | ✓ / ✓ | ✓ / — | — |
| Chat, own workspace | ✓ | ✓ | ✓ | ✓ | ✓ | — |
| "Flag for engineering" | — | ✓ | ✓ | ✓ | ✓ | — |
| Needs investigation queue: status, tuning items | — | — | ✓ | ✓ | ✓ | — |
| Retire a format version | — | — | ✓ | ✓ | — | — |
| Pre-bake-off format reset | — | — | — | ✓ | — | — |
| Rename / retire a quote | — | — | ✓ | ✓ | — | — |
| Costs screen | — | ✓ | ✓ | ✓ | ✓ | — |

The API enforces every rule, and the UI only mirrors them: `/me` returns `canReview` (decide and act) and `canRead` (read what a reviewer reads), and the navigation and the review screen hide what the caller cannot do. Scope for chat comes from the caller and the request, never from the model.

**Production (proposed).**
- Map each app role to an Entra group owned by State Fund:
  - **UW assistants** → Underwriter (review and correct);
  - **underwriters** → Underwriter;
  - **UW managers** → UWManager;
  - **the support engineers who work escalations** → Engineer;
  - **platform admins** → Admin, eligible through **PIM** with approval and time-bound activation.
- Applicant is for broker or applicant upload portals only.
- QuoteSystem goes to the quote system's managed identity or service principal: an app-role assignment, not a person's group.
- Turn off HTTP Basic (`LOSSRUN_DEV_AUTH` unset).

## 6.2 Workloads: managed identities only

No keys or connection-string secrets: every service-to-service call uses the Function App's system-assigned managed identity (`infra/rbac.tf`, `infra/integration.tf`, `infra/ledger.tf`).

| Principal | Role | Scope |
|---|---|---|
| Function App | Cognitive Services User, Cognitive Services OpenAI User | AI resource (`<ai-resource>`) |
| Function App | Storage Blob Data Owner, Storage Queue Data Contributor | Storage account |
| Function App | Durable Task Data Contributor | Durable Task Scheduler |
| Function App | Key Vault Secrets User | Key Vault |
| Function App | Monitoring Metrics Publisher | Application Insights |
| Function App | Search Index Data Contributor, Search Service Contributor | AI Search |
| Function App | Azure Service Bus Data Sender / Receiver | Service Bus namespace |
| Function App | EventGrid Data Sender | Event Grid topic |
| Function App | SQL: database user (Entra), `db_datareader`, `db_datawriter` and `EXECUTE` (changeset 0009; 0016 also grants `EXECUTE ON dbo.ApplyDecision` explicitly) | `<sql-database>` |
| SQL server identity | Storage Blob Data Contributor | Ledger digest container |
| Cost Management export | Storage Blob Data Contributor | `evals` container |
| Event Grid | Storage Blob Data Contributor | Dead-letter container |
| Load Testing | Key Vault Secrets User | Key Vault (vault scope; it reads `devauth-users`. Production: scope to that secret or drop the role) |
| Deploying user (POC) | The same data-plane roles as the Function App, plus Key Vault Secrets Officer, for operations | As above |

**Production (proposed).**
- Remove the deploying user's data-plane roles; operators get them through PIM.
- Add private endpoints, customer-managed keys where policy requires, and an Azure Policy allow-list of model deployments.
- Keep Data Zone (US) deployments, and confirm the modified abuse monitoring (`ContentLogging=false`) approval.

## 6.3 Secrets inventory

| Secret | Where | Why |
|---|---|---|
| `devauth-users` | Key Vault | Demo-host passwords, the quote system's service user included (removed in production) |
| `quote-system-api-credential`, `quote-system-api-base` | Key Vault | The mock quote system's QuoteSystem-role credential and the API address it fetches from (brief 25) |
| `quote-system-key` | Key Vault | The mock quote system's function key (the real quote system defines its own) |
| `webhook-secret` | Key Vault | HMAC key that signs `/webhooks/test` |

There is no model key, storage key or SQL password anywhere. The SQL admin is Entra-only.

## 6.4 Residual risks accepted for the POC

| Risk | Why it is accepted | Where it ends |
|---|---|---|
| **Event Grid delivers to the mock with the mock's function key in the subscription URL** (`?code=`). Anyone who reads the subscription can call the mock's `events` endpoint. | POC only, and the receiver is a mock. The key is a generated 48-character secret, held in Key Vault and the Terraform state (never committed). Reading the subscription needs Event Grid read rights on the POC resource group. Rotating the key: re-apply Terraform. | Entra-authenticated delivery (brief 30 item 50; the design and the identity team's interface in ADR 0027 §"Entra delivery to the quote system"). Built only if the organisation keeps Event Grid → mock delivery; the real quote system defines its own receiver auth. |
| **A blind-run seal without the data team's document → policy map splits by logical document, not by policy** (brief 31 item 3). One policy can then have documents on both the tuning and the blind side, so a fix tuned on its tuning documents has seen claims the blind set scores. | The map is the data team's to give; without it, `lossrun eval seal` warns and keeps the document split, so an existing seal reproduces. The residual is stated in `docs/operations/tuning-loop.md` §1 and asked for in `docs/operations/blind-run.md` §1. | `lossrun eval seal --policies <file,policyNumber csv>`: policy clusters are never split (tested). The seal-handoff step asks for the map with the archive. |
