# docs/evaluation: the data contract

These files are the **source of truth** for the canonical loss run model and its validation. Code reads them and is tested against them; code never redefines them. Research basis: `evaluation-and-wc-domain.md` (B1 schema and aliases, B2 code sets, B3 California, B4 rules, A2 comparator).

## How code consumes them
- **Embedded, not copied.** `src/LossRun.Contracts` embeds `canonical-schema.json`, `glossary.json`, `code-sets.json` and `line-of-business.json`; `src/LossRun.Rules` embeds `rule-catalog.json`. Each is linked from this folder at build time, so editing a file here and rebuilding is the only way to change behaviour. Access is through `CanonicalData.*`, `RuleCatalog.Embedded` and `RuleEvaluator.Default`. `RuleCatalog.Load(json)` and `CanonicalData.Load*(json)` accept other copies, such as a candidate catalog under review.
- **The C# model mirrors the schema.** `LossRun.Contracts.CanonicalModel.cs` is hand-written. `SchemaTests.Csharp_model_matches_schema_properties` fails if any property differs, and the synthetic 3-claim document must validate against the schema.
- **Rules are data.** `RuleEvaluator` interprets the catalog's expressions. It is pure and deterministic, with no I/O, clock or model calls, and it runs on every document, including deterministic-replay hits. The loader rejects unknown operators, undefined `forEach` vars or params, paths outside the rule's scope, unknown message placeholders, duplicate ids, and a catalog whose `schemaVersion` differs from the schema's. A test checks that every path in the catalog exists in the schema.
- **Quote rules are not document rules.** `quoteRules` (R-33) parse into `RuleCatalog.QuoteRules`; `RuleEvaluator` never reads them. `FieldStatusEvaluator` (brief 24 step 2) derives approved / unresolved / rejected per field from the review state, the hard rules still failing, `manual` lineage and `RuleCatalog.RequiredForQuoting`; `QuoteAnalytics` builds quote readiness from it.
- **A reopened claim is an open claim** for every underwriting purpose. `open_claim_count` counts `status in (open, reopened)` (catalog.yaml), and the chat filter `status: open` includes reopened (brief 24 step 7). The glossary keeps `reopened` as its own canonical status: it is a fact the run prints, and the learn prompt reads the glossary, so it is left untouched.
- **Results route.** `RuleEvaluator.Evaluate` returns a `RuleEvaluationResult` (an `IReadOnlyList<RuleOutcome>`) with `HardFailures`, `SoftFailures`, `Flags`, `PassesHardRules` and `CatalogVersion`. Flags never block and never count toward the first-pass hard-rule rate.
- **Outcomes are traceable.** Each `RuleOutcome` has `ruleId`, `severity` (after overrides), `status` (pass / fail / not-applicable), `message`, `affectedFields` (canonical field paths such as `policyPeriods[0].claims[2].indemnity.paid`, the same keys as `LossRunDocument.lineage`), `claimId`, `periodIndex`, the `forEach` bindings and, on fail, a `detail` showing the values compared, and `values` emitted for analytics (e.g. R-23 `lagDays`). This is what "show which rule fired on which cell" builds on.

## Versioning
- Versions are semver strings. **Bump on any change**: patch for wording, aliases or added codes; minor for added fields or rules; major for renamed or removed fields, or changed rule semantics.
- `schemaVersion` appears in three places: the schema's top-level keyword, `glossary.json` and `rule-catalog.json`. Tests fail unless all three agree, so a schema change forces a review of the glossary and the catalog.
- Every persisted canonical document records its `schemaVersion`. Persisted rule outcomes (ADR 0010) should record `catalogVersion`, so an old result can be reproduced with the catalog it was produced under.
- Learned mappings are **appended** to `glossary.json` `carrierProvenance` (or to the format registry). Seeded aliases are never edited in place.

## Expression language (rule-catalog.json)
- **Paths** start from `claim`, `period`, `document`, `context` (`RuleContext`: `targetPolicyEffectiveDate`, `evaluationDate`, `requestedPolicyYears`) or `item` (inside `sum`/`count`/`unique`/`collect`). `document.claims` is every claim on the run. `{var}` placeholders are bound by `forEach`, and multiple `forEach` dimensions form a cartesian product.
- **Values:** `path`, `const`, `param`, `add` (strict: null if any operand is null), `sumNonNull`, `sub`, `sum` (ignores nulls; 0 over an empty collection; null if every item is null), `count` (optional `where`), `daysBetween`, `coalesce`, `collect` (an array of item values; `transform: year` maps dates to years).
- **Predicates:** `cmp` (eq/ne/lt/le/gt/ge with optional USD `tolerance`), `and`, `or`, `not`, `allKnown` (judges only the checks whose data is present), `in`, `isNull`, `notNull`, `notBlank`, `unique` (optional `normalize: claimNumber`), `subsetOf` (every element of an array is in another; unknown when the first is null or empty).
- **Null semantics** are three-valued. A comparison with a null operand is *unknown*. A `when` that isn't true makes the rule not-applicable. For `assert`: true → pass, false → fail, unknown → not-applicable. Missing data is scored by completeness metrics, not by these rules.
  - The exception is aggregates: a printed subtotal against rows with a dropped (null) cell still fails, because `sum` ignores nulls. This is intended, since printed totals are the learn loop's free oracle.
- **Severity** is `hard` (blocks straight-through processing; counted in the first-pass hard-rule rate), `soft` (a warning) or `flag` (a routing signal: non-CA → jurisdiction split, non-WC → excluded from WC metrics, report lag, large loss).
- **Conditional severity:** `severity` is the default, and `severityOverrides` is an ordered list of `{when, severity, reason}`. The first override whose `when` is true sets the instance's severity. Examples: R-07 and R-08 are soft for cumulative trauma (CA LC 5412); R-20 is hard only when `expenseTreatment = separate`.
- **`emit`** (`{name: value-expression}`) adds non-null values to `RuleOutcome.values` on every outcome of the rule.
